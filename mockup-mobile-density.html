Select mode is the worst case today: the first card sits at y=374, and exactly two rows are visible. Two changes, and the second is the bigger one.

The bulk bar becomes one control. Its four “change a property” buttons are the same control four times — each opens a chip row and sets one field — so they collapse behind a labelled Actions ▾ button, with the count as a plain readout beside it. The count was the menu trigger in the first cut; it is not, because a label describing state never tells anyone how to act on it. × Exit goes: switching the mode select back to Search already exits, so it was a second control for one action.

On the smallest phone the readout drops its word — “✓ 128” rather than “✓ 128 selected”. Four controls and a full phrase genuinely do not fit 360px: the three fixed controls leave 78px and the phrase wants 106. Dropping a word beats ellipsising a readout into “128 select…”, and every phone wider than 360 shows it in full. It is a container query, not a media query — what ran out of room is the row.

Rows condense. A mobile card is #N (17px) + name row (31px) + type label (18px) + padding = 81px. In select mode you are choosing between entries by name, and the type is already carried by the left border colour — so the index and the type label go, leaving a 46px row that still clears the 44px touch floor. A selected row keeps its type dropdown, growing only while selected, which preserves per-row staged types and doubles as a selection cue. A setting restores full rows for anyone who wants them.

Decision 12’s parked caveat. --accent and --destructive are the same value in every theme (style.css:36/41), and the custom theme sets --destructive: var(--accent) outright. It has always been true — the FAB has always been accent — but 14B filled more controls with accent, so the collision is easier to meet: the button that creates and the button that destroys are the same red, sometimes on the same screen.
